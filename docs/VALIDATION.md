Empty/non-preview workspaces print blank. Two additional note-export PDFs had one-page checks during v0.2.0 preparation; that historical check was not repeated for this metadata/docs revision and is not counted as extra current coverage. Optional PDF checks after the browser suite: `python -m pip install -r scripts/requirements-pdf.txt`, `python scripts/check-adversarial-pdfs.py`, and `python scripts/inspect-pdf.py`.

A separate production build with `--base=/accessroute/` was served at a real `/accessroute/` mount. All 22 browser checks and six adversarial PDFs passed; temporary test copies changed only root entry URLs to the mounted path, including independently created browser pages. The mobile/touch question screen and selected-note PDF were visually inspected; the temporary server was stopped. This is local subpath evidence, not a verified public deployment. The repository suite still uses root entry URLs by default; a public subpath run must adapt those entries equivalently rather than assuming a base URL alone changes them.

These checks are software evidence, not clinical validation, a formal security assessment or complete WCAG certification. Mobile/touch are emulated. Physical devices, screen-reader speech, physical printing and native 200% zoom are not verified. Local timings do not imply device or FPS guarantees. Browser storage remains unencrypted. There is no user-study evidence.

The CI workflow has read-only repository permissions and runs model/build/browser/PDF checks. Local results do not establish remote CI success; inspect the workflow for the exact published commit. Private review correspondence, machine/session files, owner paths and unauditioned media are excluded.
